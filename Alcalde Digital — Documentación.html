01

Concepto del juego

Alcalde Digital es un juego de novela visual educativa ambientado en Ciudad Nova durante una campaña electoral. El jugador asume un rol público (ciudadano, periodista, influencer o candidato) y debe gestionar las publicaciones que circulan en Civitas, la red social ficticia de la ciudad.

Cada publicación puede ser verdadera, falsa o un rumor. Las decisiones del jugador afectan seis indicadores de la ciudad, y al final del ciclo electoral el sistema evalúa si Ciudad Nova prosperó o cayó en el caos informativo.

Por qué este tema La desinformación es una estructura de datos viva: se propaga, se ramifica y escala el riesgo. El juego convierte esa metáfora en mecánicas concretas usando las mismas estructuras que estudiamos en DS2.

Roles disponibles

Ciudadano

Amplificador ×1.0. Rol base: interactúa con información cotidiana.

Periodista

Amplificador ×1.5. Detecta noticias falsas con mayor precisión.

Influencer

Amplificador ×2.0. Sus decisiones tienen el mayor alcance en Civitas.

Candidato

Amplificador ×1.2. Construye confianza y responde publicaciones directamente.

El amplificador escala la magnitud de los puntos ganados o perdidos: una buena decisión de un Influencer tiene el doble de impacto que la misma decisión de un Ciudadano, para bien y para mal.

03

Árbol AVL — estructura central

El Árbol AVL (Adelson-Velsky y Landis, 1962) es un árbol binario de búsqueda que se mantiene balanceado automáticamente mediante rotaciones. La clave de cada nodo es el nivel_riesgo de una publicación (1–100), lo que permite ordenarlas de menor a mayor riesgo para entregárselas al jugador progresivamente.

NodoAVL

class NodoAVL:
    def __init__(self, clave, publicacion):
        self.clave = clave           # nivel_riesgo (1–100)
        self.publicacion = publicacion
        self.izquierdo = None
        self.derecho   = None
        self.altura    = 1          # altura del subárbol

Factor de equilibrio

El factor de equilibrio (FE) de un nodo se calcula como la diferencia entre la altura de su subárbol izquierdo y el derecho:

factor_equilibrio(nodo) = altura(izq) − altura(der)

Un árbol AVL garantiza que el FE de todo nodo esté en {−1, 0, +1}. Si una inserción o eliminación produce FE ±2, se aplica una rotación.

Las cuatro rotaciones

LL — Rotación simple derecha

FE = +2 en el padre y FE ≥ 0 en el hijo izquierdo. Ocurre al insertar en el subárbol izquierdo-izquierdo.

RR — Rotación simple izquierda

FE = −2 en el padre y FE ≤ 0 en el hijo derecho. Ocurre al insertar en el subárbol derecho-derecho.

LR — Rotación doble (izq → der)

FE = +2 en el padre y FE < 0 en el hijo izquierdo. Primero rotación izquierda en el hijo, luego derecha en el padre.

RL — Rotación doble (der → izq)

FE = −2 en el padre y FE > 0 en el hijo derecho. Primero rotación derecha en el hijo, luego izquierda en el padre.

Ejemplo: rotación LL en código

def _rotacion_der(self, y):        # y es el nodo desbalanceado
    x    = y.get_izquierdo()
    temp = x.get_derecho()
    x.set_derecho(y)               # x sube, y baja a su derecha
    y.set_izquierdo(temp)
    self._actualizar_altura(y)     # primero el que bajó
    self._actualizar_altura(x)
    return x                       # x es la nueva raíz del subárbol

Recorridos implementados

RecorridoOrden de visitaResultado en el juego

Posordenizq → der → raízLibera nodos en orden seguro (sin huérfanos)

Cada recorrido existe en versión recursiva y versión iterativa (ver sección 5).

04

Árbol de decisiones narrativo

Cada publicación tiene su propio ArbolDecisiones: un árbol binario que representa el camino narrativo que el jugador recorre al responderla. La raíz es la pregunta inicial; las hojas son los resultados con sus consecuencias.

Ejemplo: publicación de riesgo 75

Implementación: SesionPublicacion

class SesionPublicacion:
    def __init__(self, publicacion):
        self.actual = publicacion.arbol.raiz  # empieza en la pregunta

    def opciones(self):
        # devuelve lista de (etiqueta, 'izq'/'der') para el menú
        ops = []
        if self.actual.izquierda:
            ops.append((self.actual.izquierda.etiqueta, 'izq'))
        if self.actual.derecha:
            ops.append((self.actual.derecha.etiqueta, 'der'))
        return ops

    def terminada(self):
        return self.actual.es_hoja()  # hoja = nodo sin hijos = resultado final

El loop de Ren'Py en label nueva_publicacion: llama a sesion.opciones() para construir el menú dinámicamente y avanza el puntero actual hasta que terminada() devuelve True.

05

Lista como pila (impila / campila)

En lugar de importar una clase Stack, el proyecto usa una lista Python como pila, siguiendo el patrón definido en DS2. Los métodos impila y campila son alias semánticos de append y pop: 

def impila(self, pila, p):     # push
    pila.append(p)

def campila(self, pila):       # pop
    if pila:
        return pila.pop()
    return None

Uso en recorrido inorden iterativo

def inorden_iterativo(self, nodo):
    pila = []
    p = nodo
    while p is not None or pila:
        if p is not None:
            self.impila(pila, p)     # empila y baja por la izquierda
            p = p.get_izquierdo()
        else:
            p = self.campila(pila)   # sube cuando ya no hay izquierda
            print(p.get_clave())     # visita el nodo
            p = p.get_derecho()      # continúa por la derecha
Por qué la pila es clave aquí El recorrido inorden iterativo simula la recursión sin usar el call-stack del sistema. La pila almacena los nodos "pendientes de visitar" mientras se desciende por la rama izquierda, y los recupera en LIFO al subir. Esto es equivalente a la recursión pero con control explícito del flujo.

Uso en recorrido posorden iterativo (dos pilas)

def posorden_iterativo(self, nodo):
    pila1, pila2 = [], []
    self.impila(pila1, nodo)
    while pila1:
        p = self.campila(pila1)
        self.impila(pila2, p)                    # pila2 acumula en orden inverso
        if p.get_izquierdo(): self.impila(pila1, p.get_izquierdo())
        if p.get_derecho():   self.impila(pila1, p.get_derecho())
    while pila2:
        print(self.campila(pila2).get_clave())   # imprime en posorden

Ciudad y sus indicadores

La clase Ciudad encapsula el estado de Ciudad Nova en seis indicadores numéricos (0–100). Cuatro son positivos (sube = bueno) y dos son negativos (baja = bueno):

IndicadorTipoValor inicialQué representa
info_verificadapositivo50Porcentaje de información verificada en circulación
confianzapositivo60Confianza ciudadana en las instituciones
convivenciapositivo70Calidad de la convivencia digital y presencial
bienestarpositivo65Bienestar general de los ciudadanos
desinformacionnegativo30Nivel de noticias falsas activas en la ciudad
conflictosnegativo20Conflictos activos entre grupos ciudadanos

Derrota inmediata

Ciertos umbrales críticos terminan el juego al instante, sin esperar al final del ciclo:

def derrota_inmediata(self):
    if self.desinformacion >= 80:
        return "La desinformacion llegó al 80%. Ciudad Nova entró en pánico."
    if self.conflictos >= 80:
        return "Los conflictos llegaron al 80%. La convivencia colapsó."
    if self.confianza <= 20:
        return "La confianza cayó a 20. Los ciudadanos perdieron la fe."
    return None

Esta función se llama después de cada decisión del jugador en label nueva_publicacion. Si devuelve algo distinto de None, el juego salta inmediatamente a label derrota.

07

Jugador y roles

class Jugador:
    ROLES = {
        "Ciudadano": {"amplificador": 1.0, ...},
        "Periodista": {"amplificador": 1.5, ...},
        "Influencer":  {"amplificador": 2.0, ...},
        "Candidato":  {"amplificador": 1.2, ...},
    }

    def ganar_puntos(self, cantidad):
        self.puntos    += int(cantidad * self.get_amplificador())
        self.reputacion = min(100, self.reputacion + 2)

    def perder_puntos(self, cantidad):
        self.puntos    = max(0, self.puntos − int(cantidad * self.get_amplificador()))
        self.reputacion = max(0, self.reputacion − 2)

El jugador comienza con 50 de reputación y 0 puntos. La reputación sube +2 por cada buena decisión y baja −2 por cada mala, independientemente del rol. Los puntos sí escalan con el amplificador.

08

BancoPublicaciones — AVL en acción

La clase BancoPublicaciones es el punto de integración entre el AVL y el sistema de publicaciones. Internamente mantiene un ArbolAVL donde cada nodo almacena una publicación indexada por su nivel_riesgo.

Mejora sobre el diseño original

OperaciónDiseño original (lista)Diseño actual (AVL)
Insertar publicaciónO(1) — appendO(log n) — inserción AVL
Obtener siguienteO(n) — random.choice + removeO(log n) — _minimo_nodo + borrar
Orden de entregaAleatorio (sin control de dificultad)Ascendente por riesgo — escalada progresiva
def siguiente(self):
    # Entrega la publicación de MENOR riesgo que queda en el árbol
    nodo = self.avl._minimo_nodo(self.avl.raiz)  # O(log n)
    self.avl.borrar(nodo.get_clave())            # elimina y rebalancea
    return nodo.get_publicacion()
Por qué inorden / mínimo primero Las 10 publicaciones tienen riesgos de 10 a 90. Empezar por el más bajo garantiza que el jugador enfrenta primero situaciones simples (una campaña de reciclaje, la apertura de un hospital) y progresivamente llega a las más críticas (acusaciones de corrupción, vínculos criminales). Esto hace el juego equilibrado sin código adicional: el propio orden del AVL es la mecánica de dificultad.
09

Flujo completo del juego

1
Inicio (label start)

Se llama a intro_historia y se muestra el menú de selección de rol. El jugador elige su personaje y se inicializa jugador.rol.

2
Pantalla de espera

show screen sistema_civitas y show screen hud_ciudad. El HUD muestra los 6 indicadores en tiempo real. El loop while banco.hay_mas() mantiene el juego activo.

3
Timer de Civitas

El screen sistema_civitas usa un timer (10–20 s aleatorios) para activar postReady = True. Aparece el pop-up de notificación en la esquina superior derecha.

4
Abrir publicación (label nueva_publicacion)

banco.siguiente() extrae el nodo de menor riesgo del AVL y devuelve la publicación. Se crea una SesionPublicacion que navega el árbol de decisiones.

5
Menú de decisión

renpy.display_menu(sesion.opciones()) construye el menú desde los hijos del nodo actual del árbol de decisiones. El jugador elige, sesion.elegir(eleccion) avanza el puntero.

6
Aplicar consecuencia

Cuando sesion.terminada() es True (hoja del árbol de decisiones), aplicar_consecuencia actualiza los indicadores de ciudad y los puntos/reputación de jugador.

7
Check de derrota inmediata

ciudad.derrota_inmediata() evalúa los tres umbrales críticos. Si alguno se cumple, el juego salta a label derrota inmediatamente.

8
Repetir (publicaciones 2–10)

El timer reinicia. El AVL ahora tiene un nodo menos. El siguiente banco.siguiente() extrae la publicación de menor riesgo restante.

9
Evaluar final (label evaluar_final)

Cuando el AVL queda vacío, sistema_civitas detecta not banco.hay_mas() y lanza Jump("evaluar_final"). Se evalúan todos los indicadores simultáneamente.

10
Victoria o derrota

Si se cumplen todos los umbrales de ciudad.victoria(jugador), el jugador gana. Si no, pierde con el motivo específico.

Derrota inmediata (en cualquier momento)

CondiciónUmbralCausa típica

Confianza mínima≤ 20Ignorar pedidos ciudadanos y acusaciones

Evaluación final (después de las 10 publicaciones)

def victoria(self, jugador):
    return (
        self.info_verificada >= 50  and
        self.confianza       >= 50  and
        self.convivencia     >= 50  and
        self.bienestar       >= 50  and
        self.desinformacion  <= 50  and
        self.conflictos      <= 40  and
        jugador.reputacion   >= 60  and
        jugador.puntos       >= 50
    )
Análisis de balance Con las 10 decisiones óptimas el jugador puede acumular hasta 87 puntos y 73 de reputación. Con 6 decisiones correctas de 10 se llega al umbral mínimo de victoria (≈52 pts, ≈62 rep). El juego es gannable con margen de error pero no trivial.

Integración con Ren'Py

Ren'Py es un motor de novelas visuales que usa Python internamente. La integración funciona en tres niveles:

1. Importar clases Python en Ren'Py

# objects.rpy
init python:
    from clases.Publicacion import SesionPublicacion, BancoPublicaciones, armar_publicacion
    from clases.Ciudad import Ciudad
    from clases.Jugador import Jugador

El bloque init python: se ejecuta al inicio antes de cualquier label. Ren'Py agrega game/ al sys.path de Python, por lo que los imports funcionan sin configuración extra.

2. Variables de estado como defaults de Ren'Py

# objects.rpy
default ciudad = Ciudad()        # instancia de la clase Ciudad
default jugador = Jugador("Alcalde")
default banco   = BancoPublicaciones([...])  # AVL con 10 publicaciones

Las variables default de Ren'Py se inicializan una vez al iniciar una nueva partida y se serializan automáticamente para el sistema de guardado. Los objetos Python deben ser picklables (sin lambdas ni closures con estado).

3. Acceder a los objetos desde funciones Python dentro de Ren'Py

def aplicar_consecuencia(consecuencia):
    for clave, valor in consecuencia.items():
        if hasattr(store.ciudad, clave):          # store = namespace global de Ren'Py
            nuevo = max(0, min(100, getattr(store.ciudad, clave) + valor))
            setattr(store.ciudad, clave, nuevo)

Dentro de funciones Python definidas en init python:, el namespace de Ren'Py se accede como store. Es la forma oficial de leer y escribir variables de juego desde Python puro.

4. Timer y screens para efectos asíncronos

# screens.rpy
screen sistema_civitas():
    if not banco.hay_mas():
        timer 0.5 action Jump("evaluar_final")  # fin del juego automático
    elif not postReady:
        timer timeLeft action SetVariable("postReady", True) repeat True
    else:
        frame:
            textbutton "Abrir aplicación":
                action [
                    SetVariable("postReady", False),
                    Call("nueva_publicacion")    # llama al label Python
                ]

El timer de Ren'Py corre en paralelo al script principal. Cuando expira y postReady se activa, la pantalla re-renderiza y muestra el botón. Call("nueva_publicacion") interrumpe el loop de espera y ejecuta el label, exactamente como una llamada a función.

5. HUD en tiempo real

screen hud_ciudad():
    frame:
        align (0.5, 0.0)   # centrado en la parte superior
        hbox:
            text "Confianza: [ciudad.get_confianza()]" color "#4ade80"

Ren'Py re-renderiza las pantallas en cada frame. La interpolación [ciudad.get_confianza()] llama al método Python del objeto y actualiza el HUD al instante, sin código de actualización explícito.
