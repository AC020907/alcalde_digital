01

Concepto del juego

Alcalde Digital es un juego de novela visual educativa ambientado en Ciudad Nova durante una campaña electoral. El jugador asume un rol público y debe gestionar las publicaciones que circulan en Civitas, la red social ficticia de la ciudad.

Cada publicación puede ser verdadera, falsa o un rumor. El jugador tiene 4 posibles reacciones ante cada una. Sus decisiones afectan seis indicadores de la ciudad, y al final el sistema evalúa si Ciudad Nova prosperó o cayó en el caos informativo.

Objetivo educativo Las 4 acciones disponibles (Compartir, Verificar, Ignorar, Reportar) modelan comportamientos reales en redes sociales. Verificar antes de compartir siempre produce mejores resultados, demostrando que la responsabilidad digital tiene consecuencias medibles.

Roles disponibles

Ciudadano

Amplificador ×1.0. Rol base: interactúa con información cotidiana.

Periodista

Amplificador ×1.5. Detecta noticias falsas con mayor precisión.

Influencer

Amplificador ×2.0. Sus decisiones tienen el mayor alcance en Civitas.

Candidato

Amplificador ×1.2. Construye confianza y responde publicaciones directamente.

03

Árbol AVL — estructura central

El Árbol AVL es un árbol binario de búsqueda auto-balanceado. La clave de cada nodo es el nivel_riesgo (1–100) de una publicación, lo que permite ordenarlas de menor a mayor riesgo para entregárselas al jugador progresivamente.

NodoAVL

class NodoAVL:
    def __init__(self, clave, publicacion):
        self.clave = clave           # nivel_riesgo (1–100)
        self.publicacion = publicacion
        self.izquierdo = None
        self.derecho   = None
        self.altura    = 1

Factor de equilibrio y rotaciones

factor_equilibrio(nodo) = altura(izq) − altura(der)
# AVL garantiza FE ∈ {-1, 0, +1} para cada nodo

LL — rot. derecha

FE = +2, hijo izq FE ≥ 0

RR — rot. izquierda

FE = −2, hijo der FE ≤ 0

LR — rot. doble

FE = +2, hijo izq FE < 0

RL — rot. doble

FE = −2, hijo der FE > 0

Diagrama: AVL con las 10 publicaciones

Raíz = nodo 40 (mediana). Altura 4. Búsquedas en O(log 10) ≈ 3,3 pasos.

04

Árbol de decisiones N-ario (4 acciones)

Cada publicación tiene su propio ArbolDecisiones: un árbol N-ario que representa el camino narrativo. La raíz pregunta ¿Qué quieres hacer? y tiene tres hijos directos (Compartir, Verificar, Ignorar). El nodo Verificar tiene a su vez dos hijos (Sí → Compartir / No → Reportar), reproduciendo el diagrama del PDF (pág. 4).

Estructura del árbol (diagrama PDF reproducido)

NodoDecision — N-ario

class NodoDecision:
    def __init__(self, texto, consecuencia=None, etiqueta=None):
        self.texto       = texto
        self.consecuencia = consecuencia   # dict con efectos si es hoja
        self.etiqueta    = etiqueta         # texto del botón
        self.hijos       = []              # lista en lugar de izquierda/derecha

    def agregar_hijo(self, nodo):
        self.hijos.append(nodo)

    def es_hoja(self):
        return len(self.hijos) == 0

ArbolDecisiones con recorridos

def preorden(self, nodo, resultado=None):
    resultado.append(nodo.texto)
    for hijo in nodo.hijos:          # N-ario: iterar lista de hijos
        self.preorden(hijo, resultado)
    return resultado

def recorrido_por_niveles(self):     # BFS
    cola = deque([self.raiz])
    while cola:
        nodo_actual = cola.popleft()
        resultado.append(nodo_actual.texto)
        for hijo in nodo_actual.hijos:
            cola.append(hijo)

def avanzar(self, nodo_actual, indice):
    return nodo_actual.hijos[indice]   # índice en lugar de 'izq'/'der'

armar_publicacion — 4 acciones

def armar_publicacion(autor, contenido, es_falsa, nivel_riesgo,
                      compartir, ignorar, verificar_si, verificar_no):
    arbol = ArbolDecisiones()
    raiz  = arbol.insertar_raiz("?Que quieres hacer?")

    arbol.insertar_hijo(raiz, compartir["texto"], ...etiqueta="Compartir")
    nodo_v = arbol.insertar_hijo(raiz, "?Es verdadera?", etiqueta="Verificar")
    arbol.insertar_hijo(nodo_v, verificar_si["texto"], ...)   # Sí
    arbol.insertar_hijo(nodo_v, verificar_no["texto"], ...)   # No → Reportar
    arbol.insertar_hijo(raiz, ignorar["texto"], ...etiqueta="Ignorar")
05

Lista como pila (impila / campila)

En lugar de importar una clase Stack, el proyecto usa una lista Python como pila:

def impila(self, pila, p):   # push
    pila.append(p)

def campila(self, pila):     # pop
    if len(pila) > 0:
        return pila.pop()
    return None
Por qué la pila es clave El recorrido inorden iterativo simula la recursión sin usar el call-stack del sistema. La pila almacena los nodos "pendientes de visitar" mientras se desciende por la rama izquierda, y los recupera en LIFO al subir.

Aplicación de efectos

Los efectos se aplican desde objects.rpy mediante aplicar_consecuencia(dict), que actualiza los atributos de ciudad directamente con setattr (límites 0–100). Ciudad no tiene métodos de acción propios — solo getters para que el HUD de Ren'Py los lea en tiempo real.

# objects.rpy — aplica el dict de efectos sobre ciudad y jugador
elif hasattr(store.ciudad, clave):
    nuevo = max(0, min(100, getattr(store.ciudad, clave) + valor))
    setattr(store.ciudad, clave, nuevo)

Derrota inmediata

def derrota_inmediata(self):
    if self.desinformacion >= 80: return "Desinformación al 80%. Pánico en Ciudad Nova."
    if self.conflictos     >= 80: return "Conflictos al 80%. La convivencia colapsó."
    if self.confianza      <= 20: return "Confianza en 20. Los ciudadanos perdieron la fe."
    return None

BancoPublicaciones — AVL en acción

OperaciónLista originalAVL actual
Insertar publicaciónO(1) — appendO(log n) — inserción AVL
Obtener siguienteO(n) — random.choice + removeO(log n) — minimo_nodo + borrar
Orden de entregaAleatorio (sin control de dificultad)Ascendente por riesgo — escalada progresiva
def siguiente(self):
    nodo = self.avl.minimo_nodo(self.avl.raiz)  # O(log n)
    self.avl.borrar(nodo.get_clave())
    return nodo.get_publicacion()

Flujo completo del juego

1
Inicio

Narración introductoria + menú de rol. Se inicializa jugador.rol.

2
Pantalla de espera

HUD de 6 indicadores visible. Timer aleatorio de Civitas corre en paralelo.

3
Notificación de Civitas

Timer expira → aparece pop-up con botón "Abrir aplicación".

4
Abrir publicación

5
Menú de 4 acciones

La raíz del árbol de decisiones presenta: Compartir · Verificar · Ignorar. Si elige Verificar, aparece sub-menú: Sí / No.

6
Aplicar consecuencia

Cuando sesion.terminada() es True, aplicar_consecuencia actualiza indicadores y puntos.

7
Check de derrota inmediata

Si algún indicador cruza su umbral crítico → jump derrota.

8
Repetir x10

El timer reinicia. El AVL tiene un nodo menos. Dificultad escala automáticamente.

9
AVL vacío → evaluar final

sistema_civitas detecta not banco.hay_mas() y lanza Jump("evaluar_final").

10
Victoria o derrota

Se evalúan los 8 umbrales de ciudad.victoria(jugador).
